# SUPIR's own requirements.txt pins early-2023 versions that collide head-on with
# torch 2.7 + SM_120 (Blackwell). Deliberately relaxed here. Dropped, and why:
#
#   triton==2.1.0     torch 2.7 ships triton 3.x — the pin downgrades and breaks CUDA
#   xformers          sgm/modules/attention.py has an XFORMERS_IS_AVAILABLE fallback;
#                     torch 2.7 native SDPA is used instead (xformers wheels are
#                     torch-version-locked and would drag torch backwards)
#   transformers==4.28.1, tokenizers==0.13.3, numpy==1.24.2, Pillow==9.4.0
#                     pinned for LLaVA, which this service does not load
#   gradio*, wandb, matplotlib, pandas, scikit-learn, webdataset   UI / training only
#   facexlib, dlib    only SUPIR/utils/face_restoration_helper.py (face restore path)
#   pytorch_fid       imported lazily inside a class this service never instantiates
#
# The Dockerfile asserts torch is still 2.7.x+cu128 after this file installs, so a
# transitive downgrade fails the build loudly instead of at CUDA-kernel launch.
